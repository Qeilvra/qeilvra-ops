## Performance findings

Current auth resolves principal/status/roles/grants in one indexed query through a lazy bounded pool. Admin pages return at most 25 rows; permissions/roles are a bounded catalog. No application query-per-row loop or synchronous PDF/export exists. Correlated role arrays are SQL subqueries in one bounded list query and should be reviewed with realistic query plans, not mislabeled as separate HTTP N+1 requests.

Remaining concerns: user prefix search lower(display_name)/LIKE lacks a dedicated production-pattern index; count(*) OVER() scans matching rows; OFFSET grows with page; empty pages report total zero. User administration refetches the role catalog with every page/search/filter and current auth state is fetched again on route mounts. Debounce is unnecessary for the current submit-based search, but catalog reuse and representative EXPLAIN/latency are still needed.

Auth email delivery occurs in the worker and HTTP waits only for bounded queue handoff. Normal invite identity provisioning performs an eight-second-bounded provider request on the HTTP path; measure and review that deliberate cross-system boundary. Queue handoff is not a durable recovery scheduler, and processor effects require durable idempotency.

Final static browser asset inventory: 18 JS files, 711560 raw bytes, 221728 independently gzipped bytes across all routes. Aggregate output is not one page’s transfer budget. No new runtime dependency, icon/chart library, remote font or duplicate auth SDK was added. No API p95, production-equivalent Core Web Vitals, search latency, dashboard load or real weak-network target was measured or claimed.
